# 당황Zero Feature Scenarios

## F-01. 사전 정보 등록

사용자 목표: 사고 전 차량과 연락처 정보를 등록해 사고 발생 시 자동으로 불러온다.

선행 조건:

- 앱이 설치되어 있다.

정상 흐름:

1. 사용자가 홈에서 내 차량 정보 등록을 선택한다.
2. 차량번호, 차종, 보험사, 긴급 연락처를 입력한다.
3. 저장 버튼을 누른다.
4. 앱이 차량 정보를 Hive에 저장한다.
5. 홈에 등록된 차량 정보가 표시된다.

실패 흐름:

- 필수값이 비어 있으면 저장하지 않고 해당 필드를 안내한다.
- 로컬 저장 실패 시 재시도 버튼을 보여준다.

저장 데이터:

- vehicles

관련 화면:

- S-01 홈
- S-02 사전 정보 등록

데이터/호출:

- Hive `vehicles`

완료 기준:

- 저장 후 홈에서 등록 정보가 보인다.

## F-02. 사고 대응 시작과 안전 확인

사용자 목표: 사고 발생 직후 위치, 시간, 등록 정보를 기반으로 사고 기록을 시작하고, 부상 또는 2차 사고 위험을 먼저 확인한다.

선행 조건:

- 차량 정보가 등록되어 있다.

정상 흐름:

1. 사용자가 홈에서 사고 대응 시작을 누른다.
2. 앱이 현재 시간과 위치를 가져온다.
3. 앱이 등록된 차량 정보를 표시한다.
4. 앱이 Hive에 사고 기록을 생성한다.
5. 앱이 다친 사람 여부와 현장 위험 여부를 묻는다.
6. 사용자가 `없음` 또는 `비교적 안전함`을 선택한다.
7. 앱이 단계형 상황 파악 화면으로 이동한다.

실패 흐름:

- 위치 권한 거부 시 수동 위치 입력을 제공한다.
- 로컬 사고 기록 생성 실패 시 재시도 버튼을 표시한다.
- 다친 사람이 있거나 잘 모르겠으면 긴급 안내 화면과 전화 버튼을 표시한다.
- 앱은 전화나 신고를 자동 실행하지 않고 사용자가 버튼을 누를 때만 연결한다.
- 정식 배포 전에는 실제 112/119가 아니라 데모 번호 `010-0000-0000`으로 연결한다.

저장 데이터:

- accidents

관련 화면:

- S-01 홈
- S-03 사고 대응 시작

데이터/호출:

- geolocator
- Hive `accidents`
- Hive `triage_answers`
- optional `POST /next-action`

완료 기준:

- `accident_id`가 생성되고, 안전 확인 답변이 저장된다.

## F-03. 단계형 상황 파악

사용자 목표: 사고 유형을 직접 판단하지 않고 쉬운 질문에 답해 현재 상황 후보를 얻는다.

선행 조건:

- 사고 기록이 생성되어 있다.

정상 흐름:

1. 앱이 질문 카드를 보여준다.
2. 사용자가 버튼/칩으로 답한다.
3. 앱이 답변을 저장한다.
4. 규칙 모듈이 상황 후보 점수를 계산한다.
5. 앱이 가능성 높은 상황 후보를 보여준다.

실패 흐름:

- 답변 저장 실패 시 재시도를 제공한다.
- 상황 후보 계산 실패 시 기본 사진 기록 안내로 이동한다.
- 동점 후보가 있으면 추가 질문을 보여준다.
- 분류가 애매하면 AI가 결론을 확정하지 않고 선택지 질문을 요청한다.

저장 데이터:

- triage_answers
- situation_candidates

관련 화면:

- S-04 단계형 상황 파악
- S-05 상황 후보 확인

데이터/호출:

- Hive `triage_answers`
- Hive `situation_candidates`
- local decision core 또는 `POST /next-action`

완료 기준:

- 상황 후보가 `가능성 높음` 또는 `추가 확인 필요`로 표시된다.

## F-04. 사진 기록 안내

사용자 목표: 사고 현장에서 필요한 사진을 빠뜨리지 않고 기록한다.

선행 조건:

- 사고 기록과 상황 후보가 있다.

정상 흐름:

1. 앱이 현재 가장 중요한 사진 항목 1개를 보여준다.
2. 사용자가 사진을 촬영하거나 업로드한다.
3. 적용된 경우 전처리 모듈이 회전, 크기, 밝기, 흔들림을 검사한다.
4. 앱이 사진 파일을 앱 문서 디렉터리에 저장하고 참조와 사진 항목을 Hive에 저장한다.
5. 적용된 경우 FastAPI가 품질 결과와 PhotoFacts 후보를 반환한다.
6. CV 또는 mock PhotoFacts가 있으면 사진 관찰 결과를 저장한다.
7. 앱이 다음 촬영 요청 또는 누락 항목을 표시한다.

실패 흐름:

- 사진 저장 또는 분석 실패 시 재시도 버튼을 보여준다.
- 잘못된 파일 형식이면 업로드를 차단한다.
- 흔들림/어두움 품질 불합격이면 외부 비전 API를 부르지 않고 다시 촬영을 요청한다.
- CV 분석 실패 시 수동 항목 상태를 유지한다.
- 10초 무응답이면 같은 요청을 음성 또는 화면 강조로 다시 안내한다.

보안 시나리오:

- 로컬 사진 참조는 UUID 기반으로 관리한다.
- 원본 파일명과 개인정보를 로그에 남기지 않는다.

저장 데이터:

- accident_photos

관련 화면:

- S-06 사진 기록 안내

데이터/호출:

- camera 또는 image_picker
- app documents directory
- Hive `accident_photos`
- optional `POST /analyze/photo`
- optional `POST /next-action`

완료 기준:

- 업로드된 사진 항목, 누락 항목, 다음 촬영 요청이 표시된다.

## F-05. 체크리스트와 사고 요약

사용자 목표: 현재 상황에 맞는 초기 대응 절차와 기록 요약을 확인한다.

선행 조건:

- 사고 기록, 질문 답변, 사진 항목 상태가 있다.

정상 흐름:

1. 앱이 로컬 사고 기록 스냅샷을 읽는다.
2. Decision Core가 상황 후보와 사진 상태를 확인한다.
3. 누락 분석 모듈이 요구표에서 채워진 항목을 제외한다.
4. 계획 모듈이 NextAction 1개와 체크리스트를 선택한다.
5. 앱이 다음 행동과 체크리스트를 표시한다.
6. 사용자가 사고 요약 화면을 연다.
7. 앱이 사고 시간, 위치, 상황 후보, 사진 상태를 요약한다.

실패 흐름:

- 체크리스트 매칭 실패 시 기본 체크리스트를 표시한다.
- 요약 생성 실패 시 저장된 원본 정보를 표시한다.
- LLM 요약이 실패하면 문서 템플릿 기반 요약을 표시한다.

저장 데이터:

- checklist_results
- accidents

관련 화면:

- S-07 체크리스트 결과
- S-08 사고 요약

데이터/호출:

- Hive `accidents`, `checklist_results`
- local decision core 또는 `POST /next-action`

완료 기준:

- 체크리스트와 사고 요약이 표시된다.
