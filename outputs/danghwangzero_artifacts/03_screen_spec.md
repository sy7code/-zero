# 당황Zero Screen Specification

MVP 화면은 8개 이하로 유지한다.

## S-01. 홈

목적: 사고 대응 시작과 사전 정보 등록 진입점을 제공한다.

진입 경로: 앱 실행

주요 UI:

- 사고 대응 시작 버튼
- 내 차량 정보 카드
- 긴급 연락처 카드
- 최근 사고 기록, 선택

사용자 입력:

- 사고 대응 시작 선택
- 차량 정보 등록 선택

호출 API:

- `GET /vehicles`

성공 상태:

- 등록된 차량 정보 표시

실패 상태:

- 차량 정보 조회 실패 메시지와 재시도 버튼

다음 화면:

- 사전 정보 등록
- 사고 대응 시작

## S-02. 사전 정보 등록

목적: 사고 발생 전에 차량과 연락처 정보를 저장한다.

진입 경로: 홈 -> 내 차량 정보

주요 UI:

- 차량번호 입력
- 차종 입력
- 보험사 입력
- 긴급 연락처 입력
- 저장 버튼

사용자 입력:

- 차량번호
- 차종
- 보험사
- 긴급 연락처

호출 API:

- `POST /vehicles`

성공 상태:

- 저장 완료 후 홈으로 이동

실패 상태:

- 필수값 누락 또는 저장 실패 메시지

다음 화면:

- 홈

## S-03. 사고 대응 시작

목적: 사고 기록을 생성하고 위치/시간/사전 정보를 불러온 뒤 가장 먼저 안전 상태를 확인한다.

진입 경로: 홈 -> 사고 대응 시작

주요 UI:

- 현재 시간
- 현재 위치
- 내 차량 정보
- 다친 사람 여부 질문
- 현장 위험 여부 질문
- 112/119 전화 버튼, 긴급 후보일 때만 표시
- 위치 수동 입력 버튼
- 다음 버튼

사용자 입력:

- 위치 권한 허용
- 위치 수동 입력, 선택
- 다친 사람 있음/없음/잘 모르겠음
- 2차 사고 위험 있음/없음/잘 모르겠음

호출 API:

- `POST /accidents`
- `POST /accidents/{accident_id}/triage-answers`

성공 상태:

- 사고 기록 생성 후 안전 확인 결과에 따라 긴급 안내 또는 상황 파악 화면으로 이동

실패 상태:

- 위치 권한 거부 시 수동 입력 제공
- 서버 저장 실패 시 재시도 제공

다음 화면:

- 긴급 안내, 조건부
- 단계형 상황 파악

## S-04. 단계형 상황 파악

목적: 사용자가 사고 유형을 직접 고르지 않아도 앱이 상황 후보를 유추할 수 있게 정보를 수집한다.

진입 경로: 사고 대응 시작 -> 다음

주요 UI:

- 질문 카드
- 버튼/칩 선택지
- 잘 모르겠음 선택지
- 나중에 선택지, 사진/체크리스트 단계에서만 허용
- 진행률 표시

사용자 입력:

- 다친 사람 여부
- 차량 이동 가능 여부
- 상대 차량 여부
- 시설물 파손 여부
- 현장 위험 여부

호출 API:

- `POST /accidents/{accident_id}/triage-answers`
- `GET /accidents/{accident_id}/situation`

성공 상태:

- 상황 후보 또는 추가 질문 표시

실패 상태:

- 답변 저장 실패 시 재시도
- 상황 후보 유추 실패 시 기본 사진 안내로 이동

다음 화면:

- 상황 후보 확인

## S-05. 상황 후보 확인

목적: 앱이 유추한 상황 후보와 다음 행동을 보여준다.

진입 경로: 단계형 상황 파악 완료

주요 UI:

- 상황 후보 카드
- 가능성 높음/추가 확인 필요 표시
- 수정하기 버튼
- 사진 기록 시작 버튼

사용자 입력:

- 후보 확인
- 답변 수정

호출 API:

- `GET /accidents/{accident_id}/situation`

성공 상태:

- 상황 후보와 다음 행동 표시

실패 상태:

- 기본 사진 기록 안내 표시

다음 화면:

- 사진 기록 안내

## S-06. 사진 기록 안내

목적: 필수 사진 항목을 순서대로 한 번에 하나씩 안내하고 누락 상태를 보여준다.

진입 경로: 상황 후보 확인 -> 사진 기록 시작

주요 UI:

- 현재 요청 사진 카드
- 예시 이미지 또는 예시 설명
- 한 줄 촬영 안내
- 다시 찍기 버튼
- 건너뛰기 버튼
- 남은 항목 목록
- 업로드/촬영 버튼

사용자 입력:

- 사진 촬영
- 사진 업로드
- 항목 건너뛰기, 선택
- 10초 무응답, 이벤트로 기록

호출 API:

- `POST /accidents/{accident_id}/photos`
- `GET /accidents/{accident_id}/next-action`

성공 상태:

- 업로드 완료 표시
- 다음 촬영 요청 또는 누락 항목 표시

실패 상태:

- 업로드 실패 메시지와 재시도 버튼
- 사진 품질 불합격 시 API 분석 없이 다시 촬영 요청, OpenCV 적용 시

다음 화면:

- 체크리스트 결과

## S-07. 체크리스트 결과

목적: 상황 후보, 기록 상태, 누락 항목에 맞는 초기 대응 체크리스트와 다음 행동을 보여준다.

진입 경로: 사진 기록 안내 -> 다음

주요 UI:

- 다음 행동 카드
- 긴급 확인 항목
- 촬영 누락 항목
- 대응 체크리스트
- 항목별 출처, 출처 확인 후 표시
- 사고 요약 보기 버튼

사용자 입력:

- 체크 항목 완료 표시

호출 API:

- `GET /accidents/{accident_id}/checklist`
- `GET /accidents/{accident_id}/next-action`

성공 상태:

- 체크리스트 표시

실패 상태:

- 기본 체크리스트 표시

다음 화면:

- 사고 요약

## S-08. 사고 요약

목적: 저장된 사고 기록을 한 화면에서 확인한다.

진입 경로: 체크리스트 결과 -> 사고 요약 보기

주요 UI:

- 사고 시간
- 사고 위치
- 내 차량 정보
- 상황 후보
- 사진 항목 상태
- 체크리스트 결과

사용자 입력:

- 홈으로 돌아가기

호출 API:

- `GET /accidents/{accident_id}/summary`

성공 상태:

- 사고 요약 표시

실패 상태:

- 요약 생성 실패 시 저장된 원본 정보 표시

다음 화면:

- 홈
