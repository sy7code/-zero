# 당황Zero Decision Status Register

이 문서는 현재 산출물이 `최종 확정 계획`이 아니라 구현과 발표 준비를 위한 `작업 틀`임을 명확히 하기 위한 상태표다.

## 상태 정의

| 상태 | 의미 | 처리 방식 |
| --- | --- | --- |
| 확정 | 사용자 요청, 안전 경계, 최신 발표 방향상 바꾸면 안 되는 기준 | 문서와 코드가 이 기준을 따른다. 변경하려면 팀 합의가 필요하다. |
| 조정 가능 | 현재 기본안이지만 팀 역량, 일정, 실험 결과에 따라 바꿀 수 있는 항목 | 대체안을 남기고 구현 중 수정할 수 있다. |
| 검증 후 결정 | 실제 테스트, 공식 문서, 비용, 성능 확인이 있어야 고를 수 있는 항목 | 지금은 후보로만 둔다. MVP 필수로 쓰지 않는다. |
| 현재 결정 불가 | 외부 조건이나 팀 결정 없이는 Codex가 확정하면 안 되는 항목 | 문서에 질문으로 남기고 임의 확정하지 않는다. |
| 범위 밖 | MVP 목표와 맞지 않거나 위험해서 이번 프로토타입에서 하지 않는 항목 | 구현하지 않는다. 발표에서는 제외 사유를 설명한다. |

## 확정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 제품 위치 | 사고 판단이 아니라 초기 대응 보조 | 과실, 법적 책임, 신고 필요 여부 판단은 위험하고 공식 판단 영역이다. |
| 프론트 프로토타입 | Flutter 앱 | 사용자가 앱 프로토타입과 Flutter 프론트엔드를 명시했다. |
| UI 방향 | 3차 자료의 7개 데모 화면 흐름을 따른다 | 최신 자료가 3차이고 사용자가 그 이미지를 따라간다고 했다. |
| 안전 경계 | 과실/법적 책임/신고 필요 여부 확정 금지 | 안전, 법률, 보험 판단 위험을 줄이기 위한 경계다. |
| AI 역할 | 관찰 후보와 누락 방지 보조 | AI가 최종 판단자가 되지 않게 하기 위함이다. |

## 조정 가능

| 항목 | 현재 기본안 | 조정 가능한 대안 | 조정 조건 |
| --- | --- | --- | --- |
| 로컬 저장 | Hive + 앱 문서 디렉터리 | sqflite, Isar, SharedPreferences 일부 병행 | 팀 경험, 데이터 구조 복잡도, 사진 메타데이터 검색 필요성 |
| Flutter 상태 관리 | StatefulWidget 중심 프로토타입 | Provider, Riverpod, Bloc | 화면 수가 늘거나 상태 공유가 복잡해질 때 |
| 백엔드 | FastAPI | 로컬 mock only, Spring Boot, Firebase Functions | 팀 백엔드 역량, 배포 환경, AI/CV 연동 필요성 |
| 사진 입력 | camera 또는 image_picker | image_picker만 사용, 더미 이미지 사용 | 카메라 권한/에뮬레이터 제약, 발표 안정성 |
| 공유 기능 | share_plus | 텍스트 복사, PDF 내보내기 보류 | 발표 요구사항과 구현 시간 |
| 음성 안내 | flutter_tts | 화면 강조만 사용 | TTS 품질, 기기 설정, 시연 환경 |

| 주소 변환 API | API 비용, 네트워크, 개인정보 처리 확인 | GPS 좌표 또는 수동 위치 메모만 저장 |
| 공식 체크리스트 문구 | 경찰청/소방청/보험사 공식 자료 확인 | `source_required`로 표시하고 임시 문구 사용 |

## 현재 결정 불가

| 항목 | 왜 지금 결정 불가인가 | 다음 액션 |
| --- | --- | --- |
| 최종 발표 방식 | 라이브 데모, 영상 제출, 직접 조작 여부를 모른다 | 교수/팀 회의에서 확인 |
| 팀원별 역할 | 각 팀원의 Flutter/Python/CV 경험을 모른다 | 역할 배정표 작성 |
| 외부 API 계정/비용 | Cloud Vision/Gemini 계정과 비용 한도가 없다 | 계정 가능 여부 확인 |
| 실제 사고 사진 사용 여부 | 개인정보와 초상/번호판 처리 이슈가 있다 | 디오라마/마스킹/더미 이미지 중 선택 |
| 배포 방식 | 로컬 실행, APK, 에뮬레이터, 기기 설치 중 무엇인지 모른다 | 발표 환경 확인 |

## 범위 밖

| 항목 | 제외 이유 |
| --- | --- |
| 과실비율 판단 | 보험사/법적 판단 영역이다. |
| 법적 책임 판단 | 잘못된 안내 위험이 크다. |
| 112/119 자동 신고 | 긴급 신고 대체로 오해될 수 있다. |
| 보험사 실시간 접수 | 외부 연동, 개인정보, 인증 범위가 커진다. |
| 경찰/소방 시스템 연동 | MVP와 학생 프로젝트 범위를 넘는다. |

## 문서 사용 규칙

- `확정`이 아닌 항목은 발표나 README에서 확정 표현으로 쓰지 않는다.
- `조정 가능` 항목은 구현 중 바꿔도 되지만, 바꾸면 이 파일과 관련 설계 문서를 함께 갱신한다.
- `검증 후 결정` 항목은 실험 결과가 없으면 MVP 필수 기능으로 올리지 않는다.
- `현재 결정 불가` 항목은 Codex가 임의로 정하지 않고 팀 질문으로 남긴다.
