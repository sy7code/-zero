# 당황Zero Demo and Test Plan

## Demo Goal

평가자가 3분 안에 당황Zero가 일반 AI 챗봇과 다르게 사고 직후 대응 과정을 구조화해준다는 점을 이해하게 한다.

## Demo Script

목표 시간: 5분 이하

1. 문제 제시
   - 사고 직후 사용자는 어떤 사진과 정보를 남겨야 할지 판단하기 어렵다.

2. 앱 실행
   - 홈에서 등록된 차량 정보를 보여준다.

3. 사고 대응 시작
   - 위치와 시간이 자동 저장되는 것을 보여준다.

4. 안전 확인
   - 다친 사람 여부와 현장 위험 여부를 먼저 묻는 것을 보여준다.

5. 단계형 상황 파악
   - 사고 유형을 직접 고르지 않고, 앱 질문에 버튼으로 답한다.

6. 상황 후보 확인
   - 앱이 `경미한 접촉사고 가능성 높음`을 보여준다.

7. 사진 기록 안내
   - 한 번에 하나의 촬영 요청을 보여준다.
   - 번호판 사진을 누락한 상태를 연출한다.

8. 다음 행동/체크리스트 결과
   - 누락 항목, 다음 촬영 요청, 초기 대응 체크리스트를 보여준다.

9. 사고 요약
   - 시간, 위치, 차량 정보, 사진 상태, 상황 후보를 요약한다.

10. 디버그 근거, 선택
   - 발표 시간이 허용되면 `PhotoFacts`, `NextAction.because`, replay 여부를 보여준다.

## Fallback Demo

- 라이브 앱 실패 시 2분 이내 녹화 영상 재생
- 네트워크 실패 시 스크린샷 흐름으로 설명
- AI/CV 실패 시 feature flag off 상태의 규칙 기반 결과 시연
- 비전 API 실패 시 replay 응답 또는 mock PhotoFacts로 전환

## Demo Modes

| 모드 | 비전/CV | 사용자 | 쓰임 |
| --- | --- | --- | --- |
| 라이브 | 실제 촬영 + 가능한 경우 실제 비전 호출 | 발표자 | 본 시연 |
| 재생 | 미리 저장한 비전 응답 replay | 발표자 | 네트워크/API 불안정 대비 |
| 자동 | mock PhotoFacts + 가상 사용자 이벤트 | 시나리오 실행기 | 리허설, 녹화 영상, 회귀 테스트 |

## Diorama Demo Option

실제 사고 사진 없이 보여주기 위해 도로 매트, 모형차 2대, 가상 번호판 스티커를 사용할 수 있다.

주의:

- 디오라마 사진이 차량/번호판으로 인식되는지는 30장 시험에 포함해 먼저 확인한다.
- 인식률이 낮으면 replay 모드 또는 팀원 차량 사진의 마스킹 결과로 대체한다.
- 발표자료에는 실제 차량번호와 실제 위치를 표시하지 않는다.

## Demo Gate

외부 평가 전 다음을 만족해야 한다.

- 핵심 시나리오 3회 연속 성공
- 실패 시나리오 2개 이상 확인
- 실제 개인정보 0개
- fallback demo 준비
- known issue 작성
- 라이브/재생/자동 중 최소 2개 모드 준비
- 핵심 시나리오 12개 중 8개 이상 mock 자동 검증 통과
