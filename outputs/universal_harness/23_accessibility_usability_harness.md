# 23. Accessibility Usability Harness

이 문서는 외부 평가자가 실제로 앱이나 웹을 써볼 때 막히지 않도록 접근성과 사용성을 점검하는 하네스다.

## 1. Entry Criteria

다음 중 하나라도 해당하면 적용한다.

- 평가자가 앱/웹을 직접 조작한다.
- 모바일 화면을 시연한다.
- 입력 폼, 업로드, 권한 요청, 결과 화면이 있다.

## 2. Required Outputs

- User Flow Checklist
- Device and Viewport Matrix
- Usability Issues List
- Accessibility Notes
- Demo UX Fix List

## 3. Measurable Defaults

Core Flow:

- 핵심 흐름은 처음 사용하는 사람이 3분 이내 완료할 수 있어야 한다.
- 핵심 CTA는 첫 화면 또는 1번의 탐색 안에 보여야 한다.
- 오류 발생 시 다음 행동이 1문장으로 표시되어야 한다.

Mobile:

- 최소 360px 너비에서 텍스트가 잘리지 않아야 한다.
- 터치 대상은 최소 44px x 44px를 목표로 한다.
- 권한 거부 시 대체 입력 또는 재시도 경로가 있어야 한다.

Forms:

- 필수 입력값은 표시되어야 한다.
- 잘못된 입력은 제출 전 또는 제출 직후 알려야 한다.
- 오류 메시지는 어떤 필드를 어떻게 고칠지 말해야 한다.

Accessibility:

- 의미 있는 버튼/아이콘에는 label 또는 tooltip이 있어야 한다.
- 텍스트 대비는 일반 본문 기준 4.5:1을 목표로 한다.
- 색만으로 상태를 구분하지 않는다.

## 4. Usability Gate

다음 조건을 만족해야 외부 평가에서 직접 조작하게 한다.

- 핵심 흐름을 3분 이내 완료했다.
- 모바일 최소 너비에서 화면이 깨지지 않는다.
- 오류/빈 상태/로딩 상태가 있다.
- 평가자가 다음 행동을 묻지 않고 진행할 수 있다.
- 권한 거부 또는 업로드 실패 fallback이 있다.

실패 시 조치:

- 데모 흐름을 단순화한다.
- 입력 단계를 줄인다.
- 불명확한 버튼, 문구, 오류 메시지를 수정한다.
