# 12. Execution Checklists

이 문서는 실제 작업자가 기능 하나를 만들 때 그대로 따라가는 실행 체크리스트다.

## 1. Feature Start Checklist

기능 구현을 시작하기 전에 확인한다.

- [ ] 이 기능의 목적을 한 문장으로 썼다.
- [ ] 포함 범위를 적었다.
- [ ] 제외 범위를 적었다.
- [ ] 입력값을 적었다.
- [ ] 출력값을 적었다.
- [ ] 화면 변경이 필요한지 확인했다.
- [ ] API 변경이 필요한지 확인했다.
- [ ] DB 변경이 필요한지 확인했다.
- [ ] 외부 API 또는 모델 호출이 필요한지 확인했다.
- [ ] 개인정보 또는 민감정보를 다루는지 확인했다.
- [ ] 실패 시나리오를 최소 2개 적었다.
- [ ] 테스트 방법을 적었다.

이 체크리스트를 통과하지 못하면 구현을 시작하지 않는다.

## 2. API Implementation Checklist

API를 만들 때 확인한다.

- [ ] endpoint 이름이 명사 중심이다.
- [ ] HTTP method가 의미에 맞다.
- [ ] request schema가 있다.
- [ ] response schema가 있다.
- [ ] error response schema가 있다.
- [ ] 입력값 검증이 있다.
- [ ] 인증이 필요한 API인지 확인했다.
- [ ] 인가, owner check가 필요한지 확인했다.
- [ ] service 계층으로 로직을 분리했다.
- [ ] repository 계층으로 DB 접근을 분리했다.
- [ ] 외부 API 호출은 client 계층으로 분리했다.
- [ ] 성공 로그와 실패 로그가 있다.
- [ ] 에러 응답에 내부 정보가 없다.
- [ ] Swagger 또는 API 문서에서 확인 가능하다.

## 3. Database Change Checklist

DB를 바꿀 때 확인한다.

- [ ] 새 테이블 또는 컬럼이 필요한 이유를 적었다.
- [ ] 컬럼 타입이 적절하다.
- [ ] nullable 여부가 정해져 있다.
- [ ] default 값이 필요한지 확인했다.
- [ ] 외래키가 필요한지 확인했다.
- [ ] index가 필요한지 확인했다.
- [ ] unique constraint가 필요한지 확인했다.
- [ ] soft delete 여부를 정했다.
- [ ] created_at, updated_at 필요 여부를 확인했다.
- [ ] 기존 데이터에 미치는 영향을 확인했다.
- [ ] rollback 방법을 적었다.

## 4. Frontend Implementation Checklist

프론트 기능을 만들 때 확인한다.

- [ ] 화면의 로딩 상태가 있다.
- [ ] 성공 상태가 있다.
- [ ] 실패 상태가 있다.
- [ ] 빈 데이터 상태가 있다.
- [ ] 입력 검증 메시지가 있다.
- [ ] 네트워크 실패 메시지가 있다.
- [ ] API 응답 지연 중 중복 요청을 막는다.
- [ ] client에 secret이 없다.
- [ ] 서버 에러 메시지를 그대로 노출하지 않는다.
- [ ] 접근성 또는 모바일 사용성이 크게 깨지지 않는다.

## 5. External Integration Checklist

외부 API, 결제, AI, 모델, 지도, 스토리지 등을 붙일 때 확인한다.

- [ ] 호출 목적이 명확하다.
- [ ] 인증 방식이 정해져 있다.
- [ ] secret 저장 위치가 정해져 있다.
- [ ] timeout이 있다.
- [ ] retry 정책이 있다.
- [ ] 실패 시 fallback이 있다.
- [ ] rate limit을 확인했다.
- [ ] 비용 발생 조건을 확인했다.
- [ ] 요청과 응답 로그에서 민감정보를 제거했다.
- [ ] mock 또는 stub으로 테스트 가능하다.

## 6. Security Checklist

merge 전 확인한다.

- [ ] secret이 코드에 없다.
- [ ] `.env`가 Git에 올라가지 않는다.
- [ ] client 앱에 server secret이 없다.
- [ ] 사용자 입력을 서버에서 검증한다.
- [ ] 인증이 필요한 API에 인증 검사가 있다.
- [ ] 사용자 소유 리소스에 owner check가 있다.
- [ ] 파일 업로드 확장자 검증이 있다.
- [ ] 파일 MIME type 검증이 있다.
- [ ] 파일 크기 제한이 있다.
- [ ] 로그에 개인정보가 없다.
- [ ] 에러 응답에 stack trace가 없다.

## 7. AI Feature Checklist

AI 기능을 만들 때 확인한다.

- [ ] AI가 할 수 있는 일을 적었다.
- [ ] AI가 하면 안 되는 일을 적었다.
- [ ] prompt가 파일 또는 설정으로 분리되어 있다.
- [ ] 출력 형식을 정했다.
- [ ] 출력 검증 로직이 있다.
- [ ] 금지 출력 테스트가 있다.
- [ ] fallback이 있다.
- [ ] timeout이 있다.
- [ ] 비용과 호출 횟수를 추적할 수 있다.
- [ ] feature flag로 끌 수 있다.

## 8. Release Checklist

릴리스 또는 발표 전 확인한다.

- [ ] 앱 또는 웹이 실행된다.
- [ ] 백엔드 health check가 성공한다.
- [ ] DB 연결이 성공한다.
- [ ] 핵심 사용자 시나리오가 성공한다.
- [ ] 실패 시나리오 2개 이상을 확인했다.
- [ ] 테스트 데이터에 실제 개인정보가 없다.
- [ ] README 실행 방법이 최신이다.
- [ ] 환경변수 목록이 최신이다.
- [ ] known issue가 정리되어 있다.
- [ ] 불안정한 기능은 feature flag로 꺼져 있다.
